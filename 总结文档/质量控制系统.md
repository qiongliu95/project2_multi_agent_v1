当前项目不存在完整自动评测系统。质量控制由运行时约束、人工评测、实验治理和设计边界共同构成。

## 运行时约束

### 1. 信息来源与职责边界约束

- **解决问题**：常识补全、角色污染、跨阶段越权。
- **输入**：当前阶段规定的需求文本和上游结构化结果。
- **判断依据**：信息是否直接来自允许的数据源；是否属于当前阶段职责。
- **输出**：限定范围内的结构化结果，或空值。
- **状态**：**已实现**，通过各阶段 Prompt 进入实际调用链。
- **证据**：[需求解析约束](E:/AI-Research/project2_multi_agent/prompts/agent1a_parsing_gap_detection.md:28)、[风险约束](E:/AI-Research/project2_multi_agent/prompts/agent_2_risk_review.md:23)。

### 2. 动作覆盖与缺口分类约束

- **解决问题**：遗漏需求动作、只分析部分动作、缺口类型漂移。
- **输入**：`requirement_text`、提取出的 `main_flow`。
- **判断依据**：每个动作是否被检查；缺口是否属于 `flow/rule/scope/input_output`。
- **输出**：`action_gap_candidates`，包含 `action/has_gap/gap_type`。
- **状态**：**已实现**，同时存在 Prompt 规则和代码规范化。
- **证据**：[Prompt 规则](E:/AI-Research/project2_multi_agent/prompts/agent1a_parsing_gap_detection.md:37)、[规范化代码](E:/AI-Research/project2_multi_agent/core/agent1a_parsing_gap_detection.py:87)。

### 3. 澄清问题覆盖、去重与数量控制

- **解决问题**：问题重复、数量膨胀、关键动作未覆盖。
- **输入**：`main_flow`、`action_gap_candidates`。
- **判断依据**：仅使用 `has_gap=true` 的候选；优先覆盖不同动作；问题数量为 2～4。
- **输出**：受约束的 `open_questions`。
- **状态**：**已实现**；部分规则依赖模型遵循，代码只做类型与空值规范化。
- **证据**：[生成规则](E:/AI-Research/project2_multi_agent/prompts/agent1b_question_generation.md:30)、[输出规范化](E:/AI-Research/project2_multi_agent/core/agent1b_question_generation.py:97)。

### 4. 风险证据门控与单类别归属

- **解决问题**：通用风险枚举、风险重复分类、无证据扩写。
- **输入**：需求、解析结果、`open_questions`。
- **判断依据**：风险是否来自明确需求或待确认问题；是否满足对应风险类别触发条件。
- **输出**：六类风险数组；无依据时输出空数组。
- **状态**：**已实现**，主要由 Prompt 约束，缺少确定性后置校验。
- **证据**：[风险判断规则](E:/AI-Research/project2_multi_agent/prompts/agent_2_risk_review.md:23)。

### 5. 信息不足停止完整生成

- **解决问题**：伪完整测试、虚构步骤和规则。
- **输入**：需求解析与风险结果。
- **判断依据**：流程、输入规则和结果是否足够明确。
- **输出**：测试点和 `test_case_drafts`；不足时明确说明无法生成具体草案。
- **状态**：**已实现**为 Prompt 与 Schema 机制；没有独立确定性 Stop Controller。
- **证据**：[停止规则](E:/AI-Research/project2_multi_agent/prompts/agent_3_test_design.md:35)、[主链路调用](E:/AI-Research/project2_multi_agent/core/agent3_test_design.py:50)。

### 6. 汇总阶段禁止新增信息

- **解决问题**：Summary Drift，即汇总阶段新增问题、风险或测试方向。
- **输入**：全部上游结构化结果。
- **判断依据**：汇总内容是否能追溯到指定上游字段。
- **输出**：需求、风险和测试建议摘要。
- **状态**：**已实现**为 Prompt 约束；没有自动溯源检查器。
- **证据**：[汇总边界](E:/AI-Research/project2_multi_agent/prompts/agent_4_summary.md:6)。

### 7. 人工复核触发规则

- **解决问题**：未经确认的信息直接进入下游决策。
- **输入**：`open_questions`、`missing_info`、边界风险和测试草案。
- **判断依据**：是否仍存在缺失信息、风险或仅为草案的输出。
- **输出**：`human_review_required`、`critical_open_questions`。
- **状态**：**部分实现**。字段和判断规则已进入运行链路，但判断由模型输出，未由代码确定性计算，也没有后续审批工作流。
- **证据**：[人工复核规则](E:/AI-Research/project2_multi_agent/prompts/agent_4_summary.md:29)。

## 输出结构控制

### 8. 固定 JSON Schema 与必填字段

- **解决问题**：自然语言输出漂移、字段混杂、下游不可消费。
- **输入**：各阶段模型输出。
- **判断依据**：是否为 JSON；是否包含阶段要求的固定字段。
- **输出**：阶段结构化字典。
- **状态**：**部分实现**。所有 Prompt 定义了 Schema，但项目没有统一 JSON Schema 校验器。
- **证据**：[缺口输出 Schema](E:/AI-Research/project2_multi_agent/prompts/agent1a_parsing_gap_detection.md:88)、[测试输出 Schema](E:/AI-Research/project2_multi_agent/prompts/agent_3_test_design.md:40)。

### 9. 模型输出解析与最小兜底

- **解决问题**：Markdown fence、字段类型错误、非法缺口类型、动作遗漏。
- **输入**：模型原始文本。
- **判断依据**：JSON 是否可解析；字段类型和枚举是否合法；动作是否完整。
- **输出**：规范化后的解析结果。
- **状态**：**部分实现**。前两个阶段支持较完整规范化，后续阶段基本只有 `json.loads`，没有统一恢复与重试。
- **证据**：[缺口兜底](E:/AI-Research/project2_multi_agent/core/agent1a_parsing_gap_detection.py:63)、[问题兜底](E:/AI-Research/project2_multi_agent/core/agent1b_question_generation.py:73)。

## 人工评测

### 10. Expected Behavior Baseline

- **解决问题**：缺少预设标准，无法判断输出是正确、遗漏还是越界。
- **输入**：案例需求、Pipeline 输出、案例行为基线。
- **判断依据**：动作覆盖、问题意图、禁止假设、允许风险、停止生成和汇总边界。
- **输出**：人工标记的 `PASS/PARTIAL/FAIL` 及失败阶段。
- **状态**：**部分实现**。已有六类案例和判定规则，但主要依赖人工判断，不是自动评分系统。
- **证据**：[Baseline 结构](E:/AI-Research/project2_multi_agent/docs/expected_behavior_baseline.md:59)、[判定规则](E:/AI-Research/project2_multi_agent/docs/expected_behavior_baseline.md:778)。

### 11. 最小多案例回归规则

- **解决问题**：只修复单个案例，导致其他案例回归。
- **输入**：Prompt、Schema 或结构修改后的 Pipeline，以及固定案例集。
- **判断依据**：至少选择三个代表性案例重新运行并对照 Baseline。
- **输出**：各案例人工评测结果和问题所属阶段。
- **状态**：**部分实现**。批量 Harness 和结果归档已经实现，Baseline 对照和结论记录仍由人工完成。
- **证据**：[回归规则](E:/AI-Research/project2_multi_agent/docs/expected_behavior_baseline.md:819)、[Harness](E:/AI-Research/project2_multi_agent/main.py:77)。

### 12. 可追溯实验结果归档

- **解决问题**：不同运行结果混杂，无法进行方案对照。
- **输入**：案例、运行模式和完整 Pipeline 输出。
- **判断依据**：同批案例是否拥有统一 `run_id`；结果是否记录 `run_mode` 和各阶段输出。
- **输出**：`outputs/{run_id}/{case_id}.json`。
- **状态**：**已实现**，但只提供人工对比基础，不执行质量判断或 Diff。
- **证据**：[运行归档](E:/AI-Research/project2_multi_agent/main.py:87)、[结果保存](E:/AI-Research/project2_multi_agent/extensions/harness/result_saver.py:27)。

## 分析与过程治理

### 13. Failure Mode 分类体系

- **解决问题**：Badcase 只被当作个别 Prompt 问题，缺少系统性根因分类。
- **输入**：实验失败输出和跨阶段传播现象。
- **判断依据**：是否属于隐式补全、风险泛化、伪完整测试、角色污染、单阶段解析不稳定或汇总漂移。
- **输出**：失败类型、根因、影响和收敛策略。
- **状态**：**文档定义**，未实现自动分类器。
- **证据**：[Failure Mode Analysis](E:/AI-Research/project2_multi_agent/docs/failure_mode_analysis.md:93)。

### 14. Prompt Stop Rule

- **解决问题**：无限增加 Prompt 规则，造成复杂度上升和跨案例回归。
- **输入**：同类问题的多轮修改记录和回归结果。
- **判断依据**：问题属于哪一层、是否只影响单个案例、修改收益是否高于副作用、是否达到版本目标。
- **输出**：继续调整、转向 Schema/结构、进入扩展，或接受当前限制。
- **状态**：**文档定义**，有实际实验决策记录，但没有自动执行机制。
- **证据**：[停止规则](E:/AI-Research/project2_multi_agent/docs/output_controllability_experiments.md:472)。

### 15. Baseline Freeze

- **解决问题**：持续局部优化破坏已经相对稳定的主链路。
- **输入**：回归结果、Prompt 边际收益和修改副作用。
- **判断依据**：问题是否反复、是否跨案例迁移、是否造成下游回归。
- **输出**：冻结当前 Baseline，将后续改动移入扩展。
- **状态**：**部分实现**。文档记录了冻结决策，配置和代码支持 Baseline/扩展开关，但没有版本锁或自动保护机制。
- **证据**：[冻结决策](E:/AI-Research/project2_multi_agent/docs/output_controllability_experiments.md:659)、[配置开关](E:/AI-Research/project2_multi_agent/configs/pipeline_config.json:1)。

### 16. Extension 隔离策略

- **解决问题**：实验能力污染稳定主链路。
- **输入**：待验证的新结构或能力。
- **判断依据**：是否默认关闭、能否绕过、是否影响 Baseline 可运行性。
- **输出**：独立扩展模块和显式启用开关。
- **状态**：**部分实现**。目录和配置隔离已存在，但部分扩展资源不完整，且兼容问题分支存在输入契约不匹配。
- **证据**：[隔离规则](E:/AI-Research/project2_multi_agent/docs/output_controllability_experiments.md:778)、[条件分支](E:/AI-Research/project2_multi_agent/core/pipeline_runner.py:53)。

## 设计阶段

### 17. Context Layer 准确性验证

- **解决问题**：仅凭单段需求无法评估真实业务准确性。
- **输入**：计划中的项目背景、业务规则、页面信息、系统关系、行业信息和历史缺陷。
- **判断依据**：上下文是否可靠、相关、完整且无冲突；是否提升风险和测试设计准确性。
- **输出**：更贴近真实业务的风险和测试设计。
- **状态**：**设计阶段**，当前明确未实现。
- **证据**：[Context Layer 边界](E:/AI-Research/project2_multi_agent/docs/context_layer_boundary.md:186)。
