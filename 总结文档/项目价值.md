## 项目目标

本项目的目标不是证明“多 Agent 一定优于单 Prompt”，也不是自动生成完整测试用例。

它真正要解决的是：

> 将需求理解、风险识别、测试设计和汇总复核结构化为 AI Workflow，并控制模型在信息不足时的错误生成。

具体目标包括：

- 准确提取需求中已经明确的信息
- 将缺失信息显式转化为 `open_questions`
- 防止模型进行常识补全和业务规则假设
- 防止风险分析退化为通用 checklist
- 信息不足时停止生成完整测试用例
- 只输出 `test_case_drafts` 等可复核草案
- 保证汇总阶段不新增问题、风险或业务假设
- 保留人工复核作为最终责任边界

最新定位见 [README.md](E:/AI-Research/project2_multi_agent/README.md) 和 [System Positioning & Product Context.md](</E:/AI-Research/project2_multi_agent/docs/System Positioning & Product Context.md>)。

## 核心实现思路

项目通过四层机制控制生成过程：

| 控制层 | 作用 |
|---|---|
| Prompt Layer | 限制每个 Agent 可以使用的信息和承担的职责 |
| Schema Layer | 用固定字段表达缺口、风险、草案和人工复核状态 |
| Architecture Layer | 将任务拆成解析、缺口识别、风险分析、测试设计和汇总 |
| Process Layer | 通过 Baseline Freeze、扩展隔离和停止调优规则控制实验过程 |

因此，Multi-Agent 只是职责承载结构，真正产生价值的是分阶段约束。

## 项目价值

### 1. 将测试经验转化为可执行工作流

项目把测试人员实际执行的前置分析过程显式建模：

```text
需求理解
→ 信息缺口识别
→ 风险判断
→ 测试设计
→ 汇总复核
```

这使测试思维从个人经验变成可观察、可约束、可复用的 Workflow。

### 2. 从“生成能力”转向“输出可靠性”

项目关注六类实际失控问题：

- 隐式补全
- 风险泛化
- 伪完整测试
- Agent 角色污染
- 单阶段解析不稳定
- 汇总漂移

其价值不是让 AI 输出更多，而是降低错误信息沿 Pipeline 向下游传播的风险。相关分析见 [failure_mode_analysis.md](E:/AI-Research/project2_multi_agent/docs/failure_mode_analysis.md)。

### 3. 让不确定性成为正式输出

系统不会隐藏需求缺失，而是通过以下结构保留不确定性：

- `action_gap_candidates`
- `open_questions`
- `test_case_drafts`
- `critical_open_questions`
- `human_review_required`

这比生成一份表面完整、实际依赖假设的测试方案更可信。

### 4. 建立轻量评测基线

[expected_behavior_baseline.md](E:/AI-Research/project2_multi_agent/docs/expected_behavior_baseline.md) 已定义：

- 必须识别的动作
- 必须暴露的信息缺口
- 禁止补全的假设
- 允许和禁止生成的风险
- 测试设计的停止边界
- `PASS / PARTIAL / FAIL` 判定规则

这使项目从“人工感觉输出是否合理”推进到“依据预设行为边界判断是否越界”。

当前状态是**部分实现**：基线文档已经建立，但还不是自动评估系统，评测集也仍需扩充。

### 5. 明确产品边界

当前系统适合产出：

```text
测试设计草案
+ 待确认问题
+ 风险提示
+ 人工复核建议
```

它不适合直接产出完整可执行测试用例，因为当前输入主要是单段需求文本，缺少业务规则、页面信息、系统关系和历史缺陷。

[context_layer_boundary.md](E:/AI-Research/project2_multi_agent/docs/context_layer_boundary.md) 明确将 Context Layer 定义为二期能力，当前尚未实现。

## 总结

这个项目的核心价值可以压缩为一句话：

> 它不是一个“自动写测试用例”的 Agent Demo，而是一个研究如何让 AI 在需求不完整时不乱补、不泛化、不伪造完整答案，并输出可追溯、可复核测试草案的工作流实验。
