# Case 03 - 规则复杂需求

## 需求

为订单系统增加“优惠券自动选择”能力。

用户在提交订单前，系统需要根据当前订单自动选择一张最优优惠券，并允许用户手动切换为其他可用优惠券。

## 业务规则

优惠券可用性规则：

- 优惠券必须处于未使用状态。
- 优惠券必须在有效期内。
- 优惠券适用商品范围必须覆盖订单中的商品。
- 优惠券适用门店范围必须覆盖订单所属门店。
- 订单实付金额必须满足优惠券最低使用门槛。
- 已冻结账号不可使用优惠券。

最优优惠券选择规则：

- 优先选择优惠金额最高的优惠券。
- 优惠金额相同时，优先选择更早过期的优惠券。
- 仍然相同时，优先选择创建时间更早的优惠券。

手动切换规则：

- 用户只能切换为当前订单可用的优惠券。
- 不可用优惠券需要展示不可用原因。
- 用户手动切换后，系统不得再次自动覆盖用户选择，除非订单商品、门店或金额发生变化。

金额计算规则：

- 优惠券金额不能超过订单商品金额。
- 运费不参与优惠券抵扣。
- 使用优惠券后，订单应重新计算实付金额。

日志规则：

- 系统需要记录自动选择、用户手动切换和重新计算金额的操作日志。
- 日志字段包括用户 ID、订单 ID、优惠券 ID、操作类型、操作时间、计算前金额、计算后金额和操作结果。

## 未明确内容

- 多张优惠券是否允许叠加使用未确定。
- 订单金额变化后是否保留用户手动选择的优惠券未确定。
- 优惠券不可用原因的展示优先级未确定。
