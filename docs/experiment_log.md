# Experiment Log

## 项目目标

验证：

1. 多 Agent 拆分是否能够提升输出可控性
2. 是否可以减少模型自动补全行为
3. 是否可以在信息不足时停止生成
4. 约束设计是否比模型能力更重要

---

## Experiment 1：Single Agent Baseline

### 背景

最初尝试使用单 Agent 直接完成：

需求分析
→ 风险识别
→ 测试设计
→ 汇总输出

### 发现的问题

- 输出结构不稳定
- 容易遗漏边界条件
- 风险与测试点混杂
- 出现大量常识补全
- 信息不足时仍强行生成完整结果

### 结论

复杂任务一次性生成难以控制。

需要拆分任务职责。

---

## Experiment 2：Multi-Agent Pipeline

### 方案

引入串行工作流：

Requirement Parsing
→ Risk Analysis
→ Test Design
→ Result Summary

### 观察结果

- 输出结构明显稳定
- 各阶段职责更加清晰
- 问题定位更容易
- 仍存在模型自动扩展问题

### 结论

任务拆分有价值，但拆分本身不能解决生成失控问题。

---

## Experiment 3：Agent 1 Convergence

### 原始问题

需求解析阶段存在明显常识补全：

例如：

- 验证码
- 密码规则
- 邮箱机制

等未出现在原需求中的内容。

### 收敛措施

限制信息来源：

仅允许基于原始需求文本提取信息。

对于缺失信息：

统一进入 open_questions。

### 结果

- 常识补全大幅减少
- 信息缺口被显式暴露
- 输出更符合真实需求状态

### 结论

需求解析应以提取为主，而不是补全。

---

## Experiment 4：Agent 2 Convergence

### 原始问题

风险识别阶段倾向生成通用 Checklist：

例如：

- 权限风险
- 性能风险
- 安全风险

即使需求中没有相关信息。

### 收敛措施

限制风险来源：

仅允许引用：

- requirement_text
- Agent1 输出
- open_questions

### 结果

- 风险更加聚焦
- 不再引入无依据机制
- 风险与需求保持一致

### 结论

风险识别必须建立在已知信息基础上。

---

## Experiment 5：Agent 3 Convergence

### 原始问题

测试设计阶段存在伪完整用例问题：

即使需求信息不足：

仍会生成完整测试用例。

### 收敛措施

引入：

test_case_drafts

规则：

信息不足时：

- 允许输出测试草案
- 禁止输出完整测试用例

### 结果

- 不再伪造完整结果
- 测试设计更真实
- 信息缺失状态得到保留

### 结论

系统需要支持停止生成，而不是强行完成生成。

---

## Experiment 6：Agent 4 Convergence

### 原始问题

汇总阶段出现扩写：

Agent4 会新增问题、
新增风险、
新增设计建议。

### 收敛措施

限制汇总职责：

仅允许复用：

- Agent1 输出
- Agent2 输出
- Agent3 输出

禁止新增内容。

### 结果

- 汇总结果更稳定
- 信息来源可追溯
- 不再产生新的问题维度

### 结论

汇总层应负责整合，而不是继续推理。

---

## Experiment 7：Agent1 Three-Stage Structure

### 背景

Two-Stage 方案下：

Parsing
→ Question Generation

在复杂需求中仍存在问题遗漏和波动。

### 改进方案

引入三阶段结构：

Parsing
→ Gap Detection
→ Selection

新增中间态：

action_gap_candidates

### 结果

- 信息缺口识别更稳定
- 多动作需求覆盖率提升
- open_questions 一致性提升
- 问题来源更可解释

### 结论

中间状态比增加 Prompt 复杂度更有效。

---

## Final Conclusion

### 核心发现

多 Agent 并不会天然提升质量。

系统稳定性主要来自：

- 明确职责边界
- 信息来源约束
- 输出结构约束
- 停止生成机制

### 已验证结论

- 多 Agent 拆分是有效的
- Prompt 收敛比 Prompt 堆叠更重要
- 模型天然倾向补全缺失信息
- 信息不足时必须允许停止生成
- 中间状态能够提升系统可解释性与稳定性

### 当前边界

当前项目仅验证：

- 多 Agent 拆分价值
- 输出可控性
- 信息缺口识别能力
- 生成边界控制能力

当前不验证：

- 多模型协同
- 动态路由
- 工具调用
- 产品化系统

### 项目结论

本项目最终证明：

稳定性并非来自更多 Agent。

稳定性来自：

任务拆分 + 边界约束 + 结构控制。
